# 综述规划、证据与理论综合

需要确定综述路线、设计语料、建立编码或形成整合框架时读取。括号中的范文编号指向 [范文索引](exemplar-index.md)，它们是写作观察的依据，不是所有研究都必须遵循的格式。

## 1. 先写一张研究定位卡

| 字段 | 要回答的问题 |
|---|---|
| 目标读者的知识困难 | 读者读完哪些现有综述后，仍无法作出什么判断？ |
| 综述问题 | 哪些构念、机制、关系、条件或研究设计需要重新理解？ |
| 分析单位与层次 | 人、团队、组织、网络、产业、国家，还是关系/事件/过程？ |
| 相邻综述基线 | 对象、窗口、范围、分类、主要结论、未解决问题分别是什么？ |
| 本篇贡献目标 | 交付哪项可检查的知识变化？ |
| 范围与证据方法 | 需要哪些研究类型和来源，怎样寻找与分析？ |
| 最小有用产物 | 定义比较、类型边界、机制模型、证据裁决、用途矩阵等 |

例如，将“人工智能与组织”收窄为“AI建议与团队决策结果何时出现不同方向的效应”，才能进一步决定应编码任务类型、决策权配置、依赖程度、绩效口径和研究设计。这个例子只是问题设计示意，不断言领域已经存在这些效应。

## 2. 分别选择三个维度

| 贡献目标 | 适合的证据工作 | 可采用的组织轴 | 验收问题 |
|---|---|---|---|
| 概念澄清 | 定义、维度、测量与相近概念比较 | 实质/来源/结果；分析层次；概念演进 | 哪些概念可以比较，哪些不能混用？ |
| 理论比较与整合 | 分析单位、前提、机制、预测、边界对照 | 理论传统、机制、过程或层次 | 比旧理论集合多解释了什么？仍有何不可调和之处？ |
| 实证证据综合 | 系统检索、设计与测量编码、反例审查 | 机制、情境、研究设计；必要时元分析 | 分歧来自测量、对象、条件还是解释本身？ |
| 方法综述 | 研究用途、瓶颈、适用假设、评价标准比较 | 任务×领域×研究流程 | 方法解决了什么，仍不能解决什么？ |
| 研究版图/范围识别 | 有系统来源记录的范围梳理、内容分析 | 主题、单位、证据类型、时段 | 哪些结论只能适用于所选集合，哪些缺口确有证据？ |

不要把上述目标当互斥文类。概念澄清可以采用系统检索；理论整合可以结合元分析。九类范式指南有启发性，但混合了主题、方法与贡献维度，不能直接当作唯一标签体系。（guide_cn）

## 3. 用既有综述对照表检验必要性

建议字段：`文献、问题、窗口、来源、单位、概念边界、分类主轴、关系结构、贡献、留下的问题、本篇如何不同`。

先写既有综述的真实成就，再定位不足。有效差别包括：改变分析单位、识别跨层次混用、解释新情境为何使旧假定失效、比较竞争机制、整合以前分开的证据。只延长时间窗口或换一个热门词，不自动构成重要贡献。（en01、en02、cn07）

## 4. 建立检索与筛选记录

依据问题决定来源，而不是先限定熟悉的顶刊。记录数据库/平台、检索式、检索字段、日期、时间边界、语言、研究类型、补充追踪与每轮纳排理由。系统综述另提供去重与筛选计数；整合评述至少清楚说明选材边界和代表文献原则。

区分：

- 初检记录、去重记录、筛选后的独立研究、报告/论文、效应量数量。
- 初始来源集合、引文追踪等补充来源、最终纳入集合、正文重点展示的代表研究。
- 原文自述的方法与本次实际执行的方法；没有做过的双人筛选、一致性统计或PRISMA流程不得补写。

经典文献引用可以用于追踪，不能把“没有引用某经典”当作通用排除规则。（cn07）选取高影响范例适合学习写法，但实证主题综述不能按高引用删除反例。（guide_cn、en05）

## 5. 编码字段服务于预期判断

通用字段：`文献ID、书目、来源与版本、读取范围、单位/层次、构念定义与测量、理论前提、机制、对象/情境、数据与设计、主要发现、反向/不显著发现、识别限制、主题代码、证据位置、分析者判断`。

按目标追加：

- 概念综述：区分构念实质、前因、组成、后果与测量指标，防止循环定义；比较定义如何改变解释或设计。（en02、en03、cn02）
- 方法综述：记录用途、解决的瓶颈、方法动作、评价标准、成立假设、失败情形。（cn06）
- 元分析：另外记录样本重叠、效应量类型、换算、依赖结构、模型与调节假设；按当代方法来源核验统计程序，不照搬2010年的软件默认值。（en06）

保存代码本与裁决记录。多人编码时记录独立编码、讨论和分歧处理；单人任务如实标识，必要时做独立抽查，不能虚构多人一致性。

## 6. 进行三类综合

**概念综合**：先区分术语、实质与测量，再选有解释后果的比较维度，最后给出工作定义和未解决分歧。不要从“有好结果”倒推出概念是否存在。（en02、cn02）

**关系与机制综合**：把前因、过程、结果及条件对齐；解释这些部分为什么相连。既有过程可以交织、反馈或并行，不能因为画了四个方框便写成线性四阶段。（en03、cn04）

**矛盾综合**：先检查两项研究是否比较同一对象；再检视单位、测量、任务、时间和设计。若确有矛盾，提出相互竞争解释及区分它们所需证据；不要预设所有冲突都能用一个调节变量调和。（en05、en06）

## 7. 框架形成后的压力检查

1. 每个类别能否给出定义、边界、纳入证据与难分类案例？
2. 维度是否有理论含义，是否足以说明同一标签下的研究差异？
3. 能否容纳跨类别研究、负面后果及未解决冲突？
4. 2×2矩阵的轴能否组合，是否为了四象限而硬切材料？
5. 图中箭头的语义是否单一且明确？引用关系不等于因果，构念组成不等于时间过程。（cn02）
6. 框架只是知识地图、启发式结构、待检验模型，还是已获得证据的解释？采用对应强度的措辞。（en02）

## 8. 议程矩阵

建议列：`对应主题/框架位置、已有认识或分歧、知识限制、具体问题、竞争解释/机制、对象与数据、可能设计、关键识别或测量条件、预期理论收益`。

缺少前文依据的热点可以明确标为探索性延伸，不与证据导出的议程混写。研究机会应说明为何重要；“增加中介/调节、换地区、用新算法”本身不是解释。（cn06、cn07）
